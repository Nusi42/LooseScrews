# Loose Screws — repo guide

6DOF browser shooter with procedurally generated, destructible worlds. Rust core + WASM + TypeScript/WebGPU client.

- Docs index: `docs/README.md`; building, running, testing, adding weapons/rule sets: `docs/dev-guide.md`
- Design: `docs/design/game-design-doc.md` (exported from the living doc; source of truth for game rules)
- Plan and scope: `docs/implementation-plan.md` (read the relevant module spec before working on a crate)
- Current milestone: `docs/milestone-4-plan.md` (M4 the level has moods, approved: comedy director and events, sliders, monochrome/pigment, The Architect, workshop, audio; scope, decisions, waves, acceptance criteria, as-built notes); previous: M3 summary in `docs/milestone-3-plan.md`; visual-quality track: `docs/visual-quality-plan.md`
- Cross-crate contracts (terrain trait/edits, surface states, rock strength, mesh layers, axes, units, RNG streams, level sites: archetypes, gravity wells, the asteroid belt): `docs/architecture/contracts.md`; types live in `ls_math::terrain` and `ls_math::level`. Changing them is a cross-crate change: update the doc and all users together
- Architecture: `docs/architecture/overview.md` (crates, data flow), `netcode.md`, `determinism.md` (rules, golden hashes, re-blessing), `renderer.md` (browser renderer: HDR, post, grade hook, quality presets, GPU timing)
- Client/server glue (`ClientSession`, `Room`, wire conventions, lag compensation): `docs/architecture/game-glue.md`; server internals, browser client lifecycle, bots: `docs/architecture/server.md`
- Arsenal framework (weapon/gadget modules and hooks, ship types, entities, replication, data hash, rule set v2 and codes): `docs/architecture/arsenal-framework.md`. One module file per weapon (`crates/ls-sim/src/weapons/<family>/<id>.rs`) and gadget (`crates/ls-sim/src/gadgets/<id>.rs`), registered in `weapons/registry.rs` / `gadgets/mod.rs`; content work stays inside its module and data file
- Mode framework (M3): one module per mode (`crates/ls-sim/src/modes/<id>.rs`, `ModeModule`, registered in `modes/mod.rs`) and per mutator (`crates/ls-sim/src/mutators/<id>.rs`); settings are `ModeRules` variants in `ruleset.rs` (their field lists are part of the rule set code format: append only); replicated state is `ls_sim::ModeView` (`World::mode_view`). See `docs/architecture/arsenal-framework.md#mode-framework-m3`
- Player manual and hosting guide (all server/bot flags for hosts): `userDocs/`; the weapon, ship, gadget and mode tables in `userDocs/reference/` are generated from `data/` (modes also from `web/src/rules/catalog.ts`) (never edit them by hand)

## Where you work
- The master repo `<master>` holds `main` and only receives pushes and `git merge --ff-only WIN1`. Never edit, build, test, npm or commit there (the guards refuse). The maintainer's session runs in it and drives the clones by absolute path (`cd <clone> && ...` per command)
- Work folders (clones, `origin` = the master): `<work root>/loosescrews.win1` (branch `WIN1`, the lead: integration, full CI, memory, CodeGraph index); `loosescrews.win2`+ (`WIN2`+, one per parallel work package: on a clean tree `git fetch && git reset --hard origin/main`, commit, `git push --force-with-lease origin WINn`). New one: `node tools/work-folders.mjs create <n>` from a work folder. Decision: `docs/adr/0001-master-repo-and-work-folders.md`; how-to: `docs/dev-guide.md` "Work folders"
- Hooks: pre-commit = per-file checks on staged files, pre-push = fast CI subset (`node tools/hooks/pre-push.mjs --list`; each step's output kept in `target/pre-push/`); installed by `npm ci` in `web/`. Claude's post-edit hook runs the edited file's clone's checks and reports findings (exit 2)
- Read `.claude/memory/next-steps.md` first (project memory, first line of `MEMORY.md`): state of every work package, open questions, next steps

## If you are the lead
- Start: read `.claude/memory/next-steps.md`; `git -C <win1> fetch`; check the `WINn` branches (`node tools/work-folders.mjs status`)
- Integrate in win1: merge `origin/WINn` into `WIN1`, run `pwsh tools/ci.ps1` there; only when green: `git push origin WIN1`, then `git -C <master> merge --ff-only WIN1`. `main` is always green
- Update `.claude/memory/next-steps.md` after every finished step and before the maintainer closes a session, commit it on WIN1 and fast-forward `main` so the master's copy is current
- CodeGraph's index lives in `loosescrews.win1/.codegraph` (the master has none): pass `projectPath: <work root>/loosescrews.win1` to `codegraph_explore`, or run `codegraph explore` there
- Agents belong to the session that started them; a new session can't see or stop an older session's agents
- "Can I close this session?": report running background tasks, uncommitted/unpushed work per winN and `main` vs `WIN1` (`node tools/work-folders.mjs status`)

## Gotchas
- Never kill processes you didn't start
- Cargo runs with `-j 4` (`.cargo/config.toml`; shared machine)
- Python on Windows writes CRLF: open files with `newline=''`; write scripts to files, not heredocs with backslashes (the shell eats `\\`)
- `git stash -u` in the master can trip on locked empty folders; don't stash there (nothing should be uncommitted there anyway)
- Automated browsers (smoke, gallery, any puppeteer script, also throwaway ones) run headless only, never `headless: false` or headful fallbacks (windows pop up on the maintainer's desktop), and must inject `tools/browser-smoke/fake-pointer-lock.mjs` (`page.evaluateOnNewDocument(fakePointerLock)`): on Windows even headless Chrome's hidden windows take a real pointer lock and capture the maintainer's mouse
- Tests, bots, e2e and smoke bind `127.0.0.1` (port 0 where possible); `tools/check-binds.mjs` fails on wildcard binds outside its allowlist (Windows firewall prompts)

## Layout
- `crates/` Rust workspace crates (`ls-math`, `ls-worldgen`, `ls-sim`, `ls-net`, `ls-game` shared client/server glue, `ls-server`, `ls-wasm`, `ls-bots`, `ls-directory` optional server list service: `docs/architecture/directory.md`)
- `data/` weapon, ship, gadget, comedy event (`data/events/`, director cadence included) and rule set definitions (RON) — gameplay numbers live here, not in code; all files are embedded and hashed (`ls_sim::data_hash`, checked in the handshake)
- `web/` browser client (TypeScript strict, Vite, WebGPU, npm)
- `tools/` CI and helper scripts; work-folder guards `tools/lib/work-folder.mjs`, `tools/work-folders.mjs` (create/status/guard-master), Git hooks `tools/hooks/` + `.githooks/`, Claude hook `tools/post-edit.mjs`, `tools/check-binds.mjs`; their tests: `node --test "tools/test/*.test.mjs"`
- `docs/` developer docs; `userDocs/` player-facing manuals and hosting guides — keep them separate
- `.claude/memory/` Claude's persistent project memory (`MEMORY.md` index + one file per fact). Edit it in win1 (reaches the master via `main`); the harness memory dir is a junction to `loosescrews.win1\.claude\memory`; never store memory or project notes in temp or user folders

## Maintaining this file
Update CLAUDE.md in the same change whenever layout, commands, conventions or rules change. Keep it short: pointers and rules, not documentation (that belongs in `docs/`).

## Commands
- `cargo test --workspace` · `cargo clippy --workspace --all-targets -- -D warnings` · `cargo fmt --all`
- WASM: `cargo build -p ls-wasm --target wasm32-unknown-unknown --release` then `wasm-bindgen` (CLI 0.2.129; crate pinned to `=0.2.129`, `js-sys =0.3.106`, `wasm-bindgen-test =0.3.79` — bump all together)
- Unit tests on wasm32 (Node): set `CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUNNER=wasm-bindgen-test-runner`, then `cargo test --release -p ls-math -p ls-net -p ls-sim -p ls-worldgen --target wasm32-unknown-unknown` and `cargo test --release -p ls-game --lib --target wasm32-unknown-unknown` (the ls-sim replay hash and ls-worldgen golden hashes must match native). Test modules opt in with `#[cfg(target_arch = "wasm32")] use wasm_bindgen_test::wasm_bindgen_test as test;`
- Bot end-to-end tests (room play, the navigation sweep over 10 worlds plus a 5-minute soak-world match, the nav grid cache (`tests/nav_cache.rs`: one build per world per process, CPU per bot at least 5x lower), the in-place match transition (`tests/match_transition.rs`), `tests/arsenal_match.rs`: 8 bots, 240 s of sandbox_all_weapons, at least 15 distinct combat weapons incl. a mine and the Tectonic Charge; `tests/team_brawl_match.rs`: the Team Brawl, Instagib Brawl and duel rule sets played to a result; `tests/last_color_standing_match.rs`: 8 bots play Last Color Standing to a result; `tests/mode_matches.rs`: every mode's built-in rule set to a result with 8 bots playing its objective; `tests/social.rs`: lobby Ready, `--directory` join, duels) are ignored in debug builds: `cargo test -p ls-bots --release` (part of CI). The full match-setup sweep (8 seeds x 25 slider mixes over all seven sliders and the five level shapes, 2 and 4 teams, plus 8 x 25 asteroid belts and the belt lap fairness check) runs only in release: `cargo test -p ls-game --release --lib setup`; CI runs all of `cargo test -p ls-game --release` (setup sweep, Hot Reactor match, The Squeeze remesh benchmark, ~5 min)
- The Squeeze on generated levels (8 seeds, shell remesh benchmark, full 8-player match) runs only in release: `cargo test -p ls-game --release --test squeeze -- --nocapture`
- Worldgen timings: `cargo run -p ls-worldgen --release --example worldgen_bench` (`-- --shapes`: only the level shapes, wells and belts against the default level); per-chunk meshing over whole levels: `--example mesh_timing`; Tectonic collapse tick timing on a real level: `cargo test -p ls-game --release --test tectonic_tick`
- Player reference pages: after any change in `data/weapons`, `data/ships`, `data/gadgets`, `data/rulesets` or `web/src/rules/catalog.ts` run `node tools/gen-weapon-docs.mjs` (rewrites `userDocs/reference/*.md`); CI runs `node tools/gen-weapon-docs.mjs --check` and fails while they are stale
- Determinism cross-check (WASM worldgen golden hashes and per-mode replay hashes vs native fixtures, Node): `node tools/determinism-check.mjs` (needs the WASM package from `cd web && npm run build:wasm`; part of CI)
- After an intentional generator change: bump `ls_worldgen::GENERATOR_VERSION`, then `LS_BLESS_GOLDEN=1 cargo test -p ls-worldgen --release --test golden` (a mesher-only change re-blesses without the bump; `--test mesh_quality -- --nocapture` measures the drawn rock vs the collision surface). After a sim behavior, tuning or `data/` change: update `REPLAY_GOLDEN_HASH` in `crates/ls-sim/src/tests.rs` and re-bless the per-mode replays (`LS_BLESS_MODE_REPLAYS=1 cargo test -p ls-sim --lib golden`, fixture `crates/ls-sim/tests/fixtures/mode_replays.txt`) the world physics replays (`LS_BLESS_MOOD_REPLAYS=1 cargo test -p ls-sim --lib world_replays`, the `world/` lines of `mood_replays.txt`) and the comedy event replays (`LS_BLESS_MOOD_REPLAYS=1`, one `cargo test -p ls-sim --lib <filter>` run per harness; the filters are listed in the header of `mood_replays.txt`) (a behavior change without a `data/` change also bumps `ls_sim::SIM_BEHAVIOR_VERSION`, mixed into the handshake data hash)
- Web: `cd web && npm install && npm run typecheck && npm test && npm run build` (`npm run dev` serves on 127.0.0.1:41873 or the next free port, `LS_DEV_PORT` overrides; `?editor=rules` opens the rule set editor, `?workshop` the world workshop; `?audio=demo` the sound check page; `node web/scripts/audio-preview.ts` renders every sound to WAV + spectrogram in `target/audio-preview`; audio: `docs/architecture/audio.md`). After a data change that touches weapon names, slots, costs, levels or the default rule set: `LS_BLESS_RULES_CATALOG=1 cargo test -p ls-sim --lib rulecode` regenerates `web/src/rules/catalog.ts`. Unit tests are `src/**/*.test.ts` run by `node --test` (Node strips types: use `.ts` import extensions and erasable-only syntax, no enums/parameter properties). `npm run build:wasm` resolves a relative `CARGO_TARGET_DIR` against the repo root (use `target/<area>`, not `../target/...`)
- Play locally: `cd web && npm run build`, then `cargo run -p ls-server --release -- [--code LS..] [--ruleset <file, built-in id or LR.. code> | --playlist <file>] [--ban <weapon>]... [--balance-list <file>] [--web-root web/dist]` and open http://localhost:7777 (other flags: `--bind <addr>` (default `0.0.0.0:7777`), `--max-players`, `--stats-interval`, `--warmup`/`--countdown` (lobby, default 30/10 s; both 0 = no lobby), `--intermission`, `--private-rooms`, `--exit-when-empty`, `--wt-bind <addr>` (WebTransport UDP, default = `--bind`), `--no-webtransport`, `--directory <url>`/`--server-name`/`--region`/`--public-address <host:port>` (server list); `--help`). The browser picks WebTransport when available, else WebSocket; `?transport=ws|wt` forces one. Invite links `?join=<host:port>&party=P-..&room=R-..&code=LS..&rules=LR..`, `?servers[&directory=<url>]` opens the server list; parties/duels use the server's JSON API `/api/...` (`docs/architecture/server.md`). Bots: `cargo run -p ls-bots --release -- --count 7 [--duration 600] [--transport ws|wt] [--directory <url>] [--accept-duels] [--room R-..]` (exit 0 OK, 1 protocol error/desync, 2 never joined, 3 lost connection)
- Directory (server list, optional): `cargo run -p ls-directory --release -- [--bind 127.0.0.1:7780] [--ttl 30] [--heartbeat 10] [--max-servers] [--invite-ttl] [--max-invites] [--rate] [--burst]`; JSON API and the `DirectoryClient`/`spawn_heartbeats` library for `ls-server` in `docs/architecture/directory.md`
- End-to-end: `pwsh tools/e2e.ps1` or `tools/e2e.sh` (release server + 7 bots for 90 s with log checks; `-SkipBuild`/`--skip-build`; other options go to `tools/e2e.mjs`, e.g. `--count 8 --duration 330` for a full match, `--transport wt` for WebTransport bots, `--ruleset data/rulesets/sandbox_all_weapons.ron` for every weapon as a pickup, `--ruleset tools/e2e-rulesets/sandbox_debris.ron --min-debris 64` for debris at cap, `--max-full-per-join 1`, `--playlist quick --directory local` for every mode in rotation with in-place transitions and a local ls-directory (~11 min), `--playlist default --duration 3600 --private-rooms duel:2,team_brawl:4` for the M3 soak (public rotation, two private rooms, Welcome probes), `node tools/e2e.mjs --help`; binaries from `$CARGO_TARGET_DIR/release`; logs in `target/e2e-logs`). Not part of CI
- Browser smoke test: `pwsh tools/browser-smoke.ps1` or `tools/browser-smoke.sh` (`-SkipBuild`/`--skip-build`; headless Chrome/Edge with WebGPU via puppeteer-core in `tools/browser-smoke`: practice render, online flight firing weapons, wave C mechanics on a second server with `tools/browser-smoke/mechanics.ron`, lobby -> match -> results -> next match without a reload on a third server with `tools/browser-smoke/lobby.ron`, server list, invite links, party and a relayed duel with a local ls-directory and two servers (`social.mjs`), rule set editor, world workshop (`workshop.mjs`); screenshots and logs in `target/browser-smoke`; `node tools/browser-smoke/smoke.mjs --help`). Optional step of tools/ci.*: skipped without Chrome/Edge or with `LS_SKIP_BROWSER_SMOKE=1`
- Visual gallery (fixed-pose screenshots + per-pass GPU timing and budget check, docs/dev-guide.md "Visual gallery and GPU budget"): `cd web && npm run build`, then `node tools/browser-smoke/gallery.mjs --label <before|after>` (shots and `index.html` in `target/visual-gallery`; `?gallery=<scene>` renders one scene, `?quality=low|medium|high` forces a preset). Not part of CI
- Model screenshots (VQ4 hulls/props, before/after, object-cost bench): `node tools/browser-smoke/models.mjs` after `cd web && npm run build` (`?view=ships` in the browser; images in `target/visual-gallery/vq4`)
- Start-screen timing (time to interactive, long tasks, backdrop frame rate; headless): `node tools/browser-smoke/startup.mjs [--web-root dir] [--label name]` (dev-guide "Start-screen timing")
- Full check: `pwsh tools/ci.ps1` (Windows) or `tools/ci.sh`. Stop any Vite dev server first (on Windows it locks `web/node_modules` and CI's `npm ci` fails)
- Parallel packages use separate work folders; several cargo runs in one folder set `CARGO_TARGET_DIR=target/<your-area>` to avoid build-lock stalls

## Determinism rules (ls-math, ls-worldgen, ls-sim)
- Only IEEE-exact float ops directly; transcendental functions go through `ls_math::det` (libm). No `mul_add`, no fast-math.
- No HashMap iteration in outputs (use BTreeMap / sorted Vec), no wall-clock time, no threads, no OS RNG.
- Keep golden-hash tests passing; changing generator output requires bumping the generator version.

## Conventions
- Rust 2021, stable toolchain; workspace `rust-version = "1.85"` (also clippy's MSRV); only `ls-server` and `ls-bots` declare 1.88 (`wtransport`). `thiserror` for library errors, `anyhow` only in binaries.
- Units: 1 u = one ship length; time in ticks at 60 Hz.
- Tests next to code; every module spec in the plan has acceptance criteria — meet them.
- Don't commit; the orchestrator commits after each wave.
